输出模型（各状态直接写管脚电平）： 每个子状态在自己的函数里直接调 bspDoutSetBitmap() 写出它那一份完整电平， 没有中间状态表、没有通用 apply 包装：
relayWrite(S1_STANDBY_RELAY); —— 要合的路写 1、组内其余路写 0；
ledWrite(L_GRID_IN | ...); —— 写法与 relay 完全一致。
不做整组复位：本状态仍要合的路（如 RUN 里的 K3/K13）不会在中途被拉掉， 只把本状态不需要的路明确写 0。
RUN / RUN_OR 的顺序上电由两条轨道并行推进，每 10ms 各直接 bspDoutSetBitmap(BIT64(pin), true) 一路（AC 轨 + efuse 轨）。
WDI(PH9) 归 max6703a 模块，状态机一律不触碰；管脚只在子状态中控制，无退出清理。
需核对（md 本身不完整，已按最合理方式实现）：
  1. OFF_NO_MAINS 输出：md（T1）未给出 → 继电器保持待机回路 K3+K13（同 STANDBY），LED 暂全灭
  2. SHUTDOWN 去向：md 写 T4→T1，但"正常关机"逻辑上应回待机 → 实现为 200ms 后市电正常→STANDBY、丢失→OFF_NO_MAINS
  3. 10ms 间隔：md 描述"AC relays delay each other / DC efuse enables delay each other" → 实现为两条并行轨道（AC 轨 + efuse 轨），每轨内部 10ms 递增，两组同时起步
  4. RESET 进入：md 为 ME_BOX_ERROR && SYSTEM_RESET 上升沿 → 实现需市电正常 且 reset 上升沿； RESET 退出需 reset 释放（"3V3 && 0V"），保持 2s 后回 STANDBY / OFF_NO_MAINS

4. RUN / RUN_OR 的顺序上电时序

K2~K7 = 交流继电器，K8_1/K8_2/K9~K13 = efuse。两组同时起步， 各自内部依次延时 10ms（两条轨道并行推进，互不等待）。

S2 实现说明（源表不完整处，均已按最合理方式实现）：
  1. PAC6：六张 S2 表都有这一行，但 pin_config.xlsx Sheet2 未填它的引脚， 用户确认先留空 → 当前不控制（由于按组写电平，其实际管脚在 S2 下被写 0）
  2. 待机 / 非待机判定：市电正常（ME_BOX_ERROR 高）= 待机，掉电 = 非待机
  3. PAC2 延时关断：四张 off 表里该单元格所在列不一致 → 连接/断开推车两个方向都做延时关断
  4. LED：Excel 的 S2 表只给 PAC/PDC，没有 LED 列 → 按 S1 惯例 + S2 模式指示灯 （LED_S2_SYS_ON，solo 另加 LED_S2_SOLO_SYS）
  5. 开机态市电掉电：Excel 未定义 → 保持开机（同 S1 的 OR 模式思路），不自动关机

7. 状态日志

状态机不接受上位机指令、也没有查询 API：状态信息在迁移时直接打印到串口， 看日志即可知道当前处于哪个系统、哪个子状态。 

STATEMACHINE: init (S1 + S2)
STATEMACHINE: system -> S1          ← 系统切换（拨码变化时）
S1: -> STANDBY 上电待机 (T0)         ← 子状态迁移（每次迁移一条）
S1: -> RUN 系统开机 (T2)
S2: mode -> solo                    ← S2 子模式（pj4）
S2: -> RUN 系统开机

打印点：state_machine.c（系统切换）、sm_s1.c / sm_s2.c（子状态迁移、S2 子模式）。
串口升级（DFU）期间这些日志自动静默（terminalIsQuiet()），避免插进升级协议流。
