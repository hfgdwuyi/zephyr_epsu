Identifier names can be generated by the following recipes: 
    Identifier ::= [Special] Scope [Additionals] [Type] [ _ ] Name [ _ Unit] 
 Note: There are different rules for enum literals -- see below. 
 where [Special] 
 is an optional indicator of a type or of hardware access to memory 
 hw_ "hardware" marks a memory-mapped location 
 t_ "type" marks a type identifier 
 where [Scope] 
 is a required indication of the visibility of the identifier 
 f_ "file" for file-scope, i.e., top-level static variables 
 g_ "global" for global, i.e., top-level name space variables 
 Alternatively -- and preferably -- manage the global 
 name space by including a project or library prefix, 
 e.g., g_CPU_ -- see 4.2.1 
 l_ "local" optional for block-level auto and static variables 
 m_ "member" optional for class, struct, and union members 
 p_ "parameter" optional for function parameters 
     
 where [Additionals] 
 is an optional sequence read left-to-right of zero or more indications of access 
 indirection, const-ness, or volatile-ness 
 a "array" for array of ... 
 c_ "constant" for read-only variable; alternatively without underscore 
 h "handle" 
 p "pointer" for pointer to ... 
 v "volatile" for volatile variable 
 where [Type] 
 is an optional indicator of underlying type 
 bv "bit vector" for bit-wise -- not arithmetic – operands 
 ch "char" for character -- not arithmetic – operands 
 cl "class" or C for "class" and I for "interface class" 
 en "enum" 
 fc "function" for a subroutine, function, or method 
 fl "floating point" 
 si "signed integer" 
 st "struct" 
 ui "unsigned integer" 
 un "union" 
 vd "void" 
 where [ _ ] 
 is an optional underscore that may be present as long as it does not follow 
 another underscore
